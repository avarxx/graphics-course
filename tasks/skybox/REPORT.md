# Процедурное небо — решение

Основа — решение задания `deferred` (террейн, камни с инстансингом, G-буфер, декали, PBR).
Небо с солнцем и объёмными облаками считается compute-шейдером и запекается в cubemap, который
используется в проходе отложенного освещения.

## Структура кадра

```
0. Sky bake        compute: cubemap 6 × 2048² RGBA16F + мипы — ТОЛЬКО если параметры неба изменились
1. Depth prepass   террейн + камни
2. G-buffer pass   террейн + камни (EQUAL)
3. Decals
4. Lighting        полноэкранный треугольник; пиксели без геометрии (depth = 0) берут цвет из cubemap
```

Код: `SkyBaker.{hpp,cpp}`, `shaders/sky_bake.comp`, `shaders/SkyParams.h`, изменения в
`WorldRenderer.cpp`, `shaders/shading.glsl`, `shaders/deferred_lighting.frag`.

### Шаг 1. Cubemap, градиент и солнце

* `SkyBaker::init` создаёт изображение 2048×2048, 6 слоёв, `R16G16B16A16_SFLOAT`, флаг
  `CUBE_COMPATIBLE`, полная цепочка мипов (12 уровней). Compute-шейдер пишет в него через вид
  `2D_ARRAY` (storage image), а сэмплируется он через вид `CUBE`.
* Одна инвокация на тексель, `gl_GlobalInvocationID.z` — номер грани. Направление `rayDir` для
  текселя считается функцией `cubeTexelDir` по стандартной таблице граней Vulkan
  (+X, −X, +Y, −Y, +Z, −Z), ось Y вверх. Для всех граней используется одна и та же функция неба,
  поэтому на стыках граней нет разрывов.
* Градиент: `t = clamp(rayDir.y * 0.5 + 0.5, 0, 1)`, `mix(светло-голубой, тёмно-синий, t)` —
  на горизонте 50/50, в зените только тёмно-синий.
* Солнце: `theta = acos(clamp(dot(rayDir, sunDir), -1, 1))`, узкое свечение
  `exp(-theta² · 9000)` и широкий ореол `exp(-theta · 42)`, умноженные на цвет и интенсивность
  солнца, прибавляются к градиенту **до** облаков (облака его закрывают). Коэффициенты 9000 и 42
  и веса обоих слагаемых вынесены в ImGui.
* Направление, цвет и интенсивность солнца общие для неба и освещения террейна.

### Шаг 2. Объёмные облака

* Плотность — трёхмерный градиентный шум (Perlin-style, хэш `pcg3d`), fBm из 5 октав с поворотом
  между октавами. Порог по «облачности» (coverage) превращает шум в отдельные облака,
  высокочастотный fBm из 3 октав «подъедает» края (detail erosion).
* Облачный слой — сферическая оболочка над планетой радиуса 6360 км между нижней и верхней
  границей (по умолчанию 1500–4000 м). Кривизна даёт правильный горизонт: у горизонта лучи идут
  через слой на сотни километров, такие отрезки ограничены 40 км, а дальние облака растворяются
  в дымке (aerial perspective, `Haze distance`).
* Вертикальный профиль плотности: плавное нарастание от нижней границы
  (`smoothstep(0, 0.12, h)`) и спад к верхней (`smoothstep(1, 0.55, h)`), так что плотность
  на обеих границах слоя плавно уходит в ноль, а вершины облаков округлые.
* Ray marching: N шагов (`Primary ray steps`) по отрезку луча внутри слоя, первый шаг со случайным
  сдвигом на тексель (без него видны «слоёные» полосы). Накапливаются рассеянный свет и
  пропускание, интегрирование по шагу энергосберегающее (Hillaire 2015). Ранний выход при
  пропускании < 0.5 %.
* Самозатенение: из каждой точки облака делается M шагов к солнцу (`Shadow ray steps`), шаги
  растут к дальнему концу. Оптическая толщина `tau` даёт ослабление солнечного света.
* Освещение облака: фазовая функция — смесь двух Хеньи–Гринштейна (вперёд — серебристая кайма
  у солнца, слабое рассеяние назад) + многократное рассеяние по Wrenninge (4 «октавы» с
  ослабленной экстинкцией и более изотропной фазой; без этого облака серо-синие, хотя их альбедо
  ≈ 1) + рассеянный свет неба, которого у нижних частей облаков меньше.
* Запись: `RGB = градиент·T + свет облаков`, `A = T` — пропускание облачного слоя вдоль направления.

### Шаг 3. Небо в отложенном освещении

* В `deferred_lighting.frag` пиксели с глубиной 0 (reverse-Z, буфер очищен в 0) — это небо.
  Направление восстанавливается по экранным координатам обратной матрицей ViewProjection
  (та же `invViewProjRel`, что и для позиции, — без трансляции камеры, поэтому результат и есть
  направление взгляда), и читается cubemap (`textureLod(..., 0)`: неявные производные в
  неоднородном ветвлении «небо / не небо» не определены).
* Запечённое небо используется и для освещения поверхностей (флажок в ImGui, можно вернуть
  плоский цвет для сравнения):
  * диффузный ambient — сильно размытый мип (4×4 на грань) в направлении нормали;
  * отражения неба — мип по шероховатости;
  * цвет тумана — небо над горизонтом в направлении взгляда, так что даль сливается с небом;
  * пропускание облаков в направлении солнца (`A` cubemap'а, размытый мип) ослабляет солнечный
    свет: когда солнце за облаком, остров в тени (`Cloud shadow on sunlight`).
* Форвардный эталон из прошлого задания тоже рисует небо (`sky_forward.frag`) и использует тот же
  код освещения. Скриншоты forward и deferred без декалей совпадают (макс. разница 1/255).

### Шаг 4. ImGui и запекание только при изменениях

* Секция **Sky and sun**: азимут, высота, интенсивность и цвет солнца; цвета градиента и яркость;
  веса и резкость свечения и ореола; облака вкл/выкл, облачность, плотность, масштаб,
  нижняя/верхняя граница слоя, число шагов основного и теневого лучей, а также эрозия, рассеяние
  вперёд, свет на облаках, дымка, сдвиг шума.
* `SkyBaker::drawGui` и `setSun` выставляют флаг `dirty` только при реальном изменении параметров;
  `bakeIfNeeded` в начале кадра запекает cubemap только при `dirty`, иначе используется готовая
  текстура. В ImGui видно число запеканий и GPU-время последнего (`Sky bake`).
* После запекания цепочка мипов строится блитами (ручные барьеры по мипам, в конце все мипы
  возвращаются в `TRANSFER_DST`, чтобы трекер состояний etna, который следит за изображением
  целиком, снова был прав).
* `Faces per frame`: для слабых GPU запекание можно растянуть на несколько кадров (по граням).
  Первое запекание всегда целиком.

## Проверка

* Сборка с `-Wall -Wextra -Werror -pedantic` (gcc 13), clang-format.
* Validation layers c synchronization validation (deferred и forward, с запеканием и мипами) —
  без сообщений.
* За 30 кадров без изменений параметров — ровно одно запекание (`Sky cubemap baked (bake #1)`
  в логе).
* Программный Vulkan (lavapipe, 2 ядра CPU): запекание 2048² — около 70 с, 512² — около секунды.
  На видеокарте это порядка сотен миллисекунд; если на слабом GPU долго, уменьшите число шагов
  или включите `Faces per frame`.
